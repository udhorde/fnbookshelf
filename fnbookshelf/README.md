# 飞牛书屋 (fnbookshelf)

自托管电子书阅读应用 · 飞牛 fnOS .fpk 安装包 · 当前版本 **1.9.4**

## 1.9.4 改动：「端口被占用」不再无解

1. **改端口真正生效**。有用户反馈「一直提示端口占用，改了端口号都没用」。根因在配置回写脚本：配置文件已存在但里面没有端口行时，替换命令会静默跳过、不新增端口行，写失败也不报任何错——应用于是永远按旧端口启动，撞的还是原来那个占用者，换多少次端口都没用。现在改为整段重写（剔除旧端口行、写入新端口行、原子落盘），成功与失败都会写进安装日志；手工编辑配置文件带回车符等问题也一并兼容。
2. **报错自带线索**。「端口已被占用」的提示现在会注明**当前端口来自哪里**（配置文件里的 APP_PORT，还是默认值 8096）。已改过端口、提示的仍是旧端口号，就能一眼看出是「端口没写进配置」而不是「新端口也被占」，按提示重新保存一次即可；真被别的服务占用时，也能对准端口号去处理。

## 1.9.3 改动：退出不再卡住，页面不再留灰底，合并一次到位

1. **退出阅读器不再卡死**。点「退出」后外框还留在屏幕上、内容已经消失、整页无法再操作，只能刷新。根因是上一版把「APP 返回键」的接管函数写成了函数内的常量，退出时读它会直接抛错，而抛错的位置正好在「移除阅读器外框」之前。现在改为页面级变量，退出流程的每一步都单独兜底，**外框、页码条、滚动锁一定会清干净**，关掉可以立刻再打开。
2. **PDF / PPT 每页底部的大段灰底**。部分分辨率下（尤其是横向页和窄窗口），每页下方会多出一条和页面等宽的灰底空白。原因是占位高度按「视口宽度」算、实际宽度却被最大宽度限制压小了，高度没有同步。改为按**每页真实宽高比**占位，渲染完立刻收掉占位，横竖混排的 PDF 也不再留白。
3. **合并一次到位（真正的修复）**。上一版按作品键聚合候选，但《甲作品 卷1 / 卷2 / 卷3》的键各不相同，永远聚不到一起。现在候选列表按「作品键 → 同目录同族 → 同目录同书名主干」三层并查集聚合，一行就是一部作品，显示「N 个文件」，点「合并全部 N 个文件」一次性并进来，不再一本一本挪。

## 1.9.2 改动：入库不再串号，筛选与返回更顺手

1. **书名不再被刮削改错**。以前只要刮削到一条结果就整条覆盖，五级线索（文件名 → 内嵌元数据 → 目录名 → 正文抽样）一旦偏到同目录的另一本书，就会出现「本来叫《小学数学-思维导图》，入库却成了《01初中数学1.1》」。现在以文件名为准：文件名可信时不会被刮削名覆盖；同目录里另一本书已经占用这个标题时判定为串号，直接拒绝。
2. **乱码书名反向覆盖修复**。《我不(大冰).pdf》入库后变成乱码，原因是元数据救不回来时去比「像不像人话」，结果把正常的文件名换成了乱码。现在只要文件名本身不像乱码就直接采信。
3. **刮削状态说得清楚**。详情页区分「⏳ 正在后台补全简介、封面与出版信息…」与「⚠ 未刮削到书籍信息」；后者给管理员一个「编辑资料」入口，也可以在重新刮削时自己指定检索书名。
4. **筛选按钮**。全部图书与专题列表都有独立的「🔎 筛选」按钮，按格式、出版社、作者多选；选项分组默认折叠，**点「确定」才生效**，翻页、滚轮、按 Esc 都会自动收起，不占屏幕空间。已生效的条件在按钮下方用 chips 摘要显示，可单点取消。
5. **合并一次到位**。合并候选列表改成按作品聚合，一部作品里有几个文件就显示「N 个文件」，点「合并全部 N 个文件」一次性并进来，不再一次只挪一本。
6. **APP 返回键回上一层**。以前走浏览历史：书库里点 A 书 → 返回 → 点 B 书 → 返回，会退回 A 书。现在按路由层级计算，书详情返回来时那份列表，**连筛选和搜索词一起还原**；专题详情返回专题总览，专题总览返回书架。
7. **朗读能用**。分块阅读的 TXT 以前只能取到当前一屏，现在取全部已加载段落；扫描件 PDF 与纯图片幻灯片不再说「当前页面没有可朗读的文字」，而是说明「这一页没有文本层（多半是扫描件或图片页）」。
8. **PPT 旧对象说明**。「不支持编辑的旧版 OLE 对象」改为「嵌入对象（原文件里是表格/公式等外链内容，无法直接显示）」；导出 PDF 时会在角上提示本页有几处源文件嵌入对象没能显示。

| 📚 图书管理 | 管理员添加 NAS 本地路径，应用只关联读取，**不搬运、不重命名**任何文件；**定时自动扫描**（1.9.1 起在「扫描与刮削」里自由设定周期：每 N 小时 / 每 N 天 / 每周几 / 每月某日，可顺带自动刮削；分批进行，启动 5 分钟后补扫；若上次是异常退出则跳过补扫，避免重启后又崩）；管理员在书籍详情页能看到**文件的完整存储路径**（点击复制），排查「这到底是哪个文件」不用再进 NAS 翻目录 |

| 🧩 版本管理 | **同名书扫描后自动合并**（书名相同即先归到一起；每次自动扫描都会复查并合并一次，刮削拿到新书名后同样会自动合并；刮削拿到可信作者后发现是两本不同书才自动拆开）；**同目录下文件名只差期号/年份的自动聚合成「×× 系列」**（如《人民日报》各期、2013/2014 社论），详情页里各期就是一个个版本；**即使只有一个版本也常显版本栏并列出当前文件**；「编辑」里可**搜索并手动合并其他书籍**、**把某个版本分离成独立书籍**（分离后不再被自动合并）；每行按钮固定为**阅读 → ⬇ 下载 → 申请删除**（可直接下载该版本的原始文件），另有设置默认版本；1.9.0 起可**上下移动调整版本顺序**（第一版就是默认展开的那个），「编辑」里还能**勾选多个搜索结果批量合并**进来。书库顶部「☑ 批量」进入多选模式后用**自绘指针拖拽**（不再用 HTML5 draggable，绝不误触发浏览器搜索页），也可点选两本书合并；**合并/分离不再弹二次确认**，编辑模式下可勾选多个版本批量分离，或一键「全部打散」把整个作品拆成独立书籍 |
| 🌳 按路径合并 | 管理后台「图书库 → 按路径批量合并」按**真实目录结构**列示（和 Windows 资源管理器一样可折叠、可整目录勾选），列的是「一个目录里还散着多部作品」的情况，勾选后只改索引不动文件 |
| 📌 顶栏常驻 | 全部图书与专题列表向下滚动时，**搜索 / AI找书 / 批量 / 改专题**（含格式筛选）始终悬浮在页面顶部；「删专题」属破坏性操作，**仅管理员可见** |
| 🗑 删除审核 | 删除先生成申请；若该版本有用户书签/笔记，**弹窗明确列出是哪些用户**；管理员二次确认后文件移入回收站（不物理销毁）；回收站每条都能**恢复**或**清空**，**进入回收站 30 天后自动删除** |
| 📖 在线阅读 | EPUB（epub.js）、PDF（pdf.js 分块）、MOBI/AZW3/AZW/PRC（foliate-js）、**TXT/MD（编码自动识别 + 分块按需加载，几百 MB 也不卡）**、**Word（.docx / .doc）**、CBZ 漫画、**PPT/PPTX（浏览器内直接逐页渲染，旧版二进制 .ppt 也支持，文字可选、缩放不糊；可一键「存为 PDF」作为新版本入库，同一个文件只转换一次）** |
| 🧭 自动目录 | EPUB nav/NCX、TXT/MD 章节识别、**Word 标题层级（.docx 按 Heading 样式、.doc 按段落格式）**、PPTX 页标题、PDF 内置大纲；侧栏抽屉点击跳转；目录独立缓存文件，不撑大数据库 |

| 🗂 入库文件类型 | 管理后台「图书库」里可逐项勾选允许入库的后缀（epub/pdf/txt/md/doc/docx/ppt/pptx/cbz/mobi…），也能额外填要排除的后缀；取消勾选后下次扫描直接跳过，NAS 源文件不动，重新勾上即回到书库 |
| 📁 专题 | 侧栏里「🗂 专题」与「📚 全部图书」**平级**（排在它下面，不缩进成子项），点进去是专题总览，像文件夹一样把书按主题归类（如「中国史入门」「待读的科幻」）；管理员点「☑ 选择」可多选，**搜索结果里也能批量建专题**，或批量加入/移出已有专题；专题只记分类关系——文件不移动、书不删除，一本书可以同时在多个专题里，移除专题也不影响书库；1.9.0 起**专题可设置自己的封面**（上传图片，或借用专题里某本书的封面），把书加进专题时**弹窗可一次勾选多个专题**批量加入/移出；书籍详情页新增**专辑管理**，直接看到这本书在哪几个专题里，一键加入/移出/新建 |
| 📱 客户端 | 提供**手机/平板版**与 **TV 版**两个安卓客户端；页面左侧栏底部「📱 下载 APP」进入下载页，管理员在「管理后台 → APP 安装包」上传新包（填版本号即写入），**APP 启动时自检版本，发现新版自动下载并调起系统安装**；APP 内「下载管理」可查看已保存到「下载 / 飞牛书屋」的文件，支持打开、分享、删除 |

| 🔢 页码直达 | 全部图书底部显示「共 N 本」与分页条，可直接输入页码回车跳转，不必一页页点；右侧新增**每页 24 / 48 / 96 / 200 本**下拉，会记住上次选择 |
| 🎚 PDF 画质 | 阅读设置里新增 **PDF 亮度 / 对比度**两个滑杆（只作用于页面图像，不影响界面），老扫描件底色发灰、字发虚时调一下立刻清楚；设置会记住，可一键恢复默认 |

| 🔊 TTS 朗读 | 默认浏览器本地语音（离线）；可切换 OpenAI 兼容或 Azure 语音；管理后台**可一键全局关闭**（关闭后阅读器不再显示朗读按钮） |

| 📱 移动端 | ≤760px 抽屉导航 + 自适应栅格；阅读器工具条横向滚动、设置面板贴底全宽 |
| ✈️ 离线优先 | 除「在线刮削」「AI」「云端 TTS」三个可选能力外，阅读、目录、朗读、统计、笔记全部内网离线可用，不依赖任何 CDN |

## 支持的格式

| 格式 | 元数据 | 在线阅读 |
|---|---|---|
| epub | ✅ 完整（含封面/目录） | ✅ 分页、可高亮（CFI 定位） |
| pdf | ✅ | ✅ **Range 分块按需加载**，大文件首屏秒开 |
| mobi / azw3 / azw / prc | ✅ | ✅ 内置 foliate-js 渲染（保留排版/图片/链接） |
| txt / md | 文件名 + 正文首部「书名/作者」 | ✅ **编码自动识别**（UTF-8 / UTF-16 / GB18030 / GBK / Big5）+ **分块按需加载**，自动分章 |
| cbz | ✅ 首图封面 | ✅ 图片翻页 |
| **ppt / pptx** | ✅ | ✅ **浏览器内直接渲染**（内置 `@web-ppt/core`，`.pptx` 与旧版二进制 `.ppt` 都支持）：逐页 SVG、文字可选中、缩放不糊；另可一键「存为 PDF」把当前渲染结果作为本书新版本入库 |
| cbr / djvu / fb2 | 部分 | 下载后本地阅读 |
| **doc / docx** | ✅（.docx 内嵌属性） | ✅ **在线直接阅读**：.docx 解析 OOXML 正文并保留粗体/斜体/标题层级，.doc 走 OLE 片段表（失败时退化为启发式编码扫描）；目录按标题自动生成 |
| rtf / chm / html | 部分 | 下载后本地阅读 |

> **PPT 说明（1.6.3 起默认浏览器直接渲染）**：阅读器把原文件取回浏览器，用随包的 `@web-ppt/core`（MIT / 约 400 KB / 无框架依赖 / 不联网 / 不上传）解析后逐页输出 SVG——文字是真实文字（可选中、可搜索），图片按 data URL 内嵌，缩放不糊，`.pptx` 与 1997–2003 二进制 `.ppt` 共用同一条渲染通道。渲染在浏览器完成，因此不再受 NAS 目录权限、服务端内存或 LibreOffice 缺失影响。1.6.2 的服务端链路（`.pptx` 走 OOXML 抽整页图、`.ppt` 走 OLE `Pictures` 流按 `pib` 对页）**仍保留**为「⚙ 后台转换为 PDF」与「逐页绘制（兼容模式）」兜底；「存为 PDF」则改为浏览器逐页光栅化后交给服务端合成，结果与屏幕所见一致。
> ZIP 类（EPUB/CBZ/PPTX/DOCX）不再整本读入内存：内置轻量 ZIP 读取器只解析中央目录、按需解压所需条目。实测一本 64MB 的 EPUB，读元数据内存占用从 64MB 降到约 1MB；超过 1GB 的极端文件或超大单条目会跳过深度解析。

> 1.8.1 → 1.8.2 主要变化：**刮削依据重排**（文件名 → 文件信息 → 目录层级 → 正文抽样，垃圾书名不再参与检索）；**详情页刮削完成后不再整页刷新**（以前会把正在操作的内容冲掉）；**新增专题**（像文件夹一样归类，支持搜索后批量建专题）；**版本管理去二次确认 + 批量分离 + 一键打散**；分页加「每页多少本」下拉；**修复 3 万多本的大书库扫到一半被系统杀掉**（落盘改流式写入，峰值内存降 3 倍）。升级后首次打开请按一次 **Ctrl+F5** 强制刷新。

## 稳定性与日志

- **按需读取（1.4.1 核心修复）**：旧版扫描 EPUB/CBZ/PPTX 时 `AdmZip` 会把整本书同步读进内存，一本 EPUB 在一次扫描里还会被读 2～3 次（元数据、目录、抽样重刮），167 本连着处理极易触发 NAS 的 OOM 保护而被无声杀掉。现改为自研 ZIP 读取器：只解析中央目录、按需解压单个条目，并限制单条目压缩数据 / 解压结果各 32MB、抽样解压流 12MB、中央目录 24MB、整文件 4GB（防压缩炸弹）；扫描层对超过 1GB 的书跳过深度解析。内存占用与书籍体积无关
- **卡死防护**：数据库异步落盘（防抖 + 写入锁）、目录缓存外移、扫描每文件让出事件循环；TXT/FB2 只读前 4MB；目录读取 15 秒超时、单本 1 分钟、整轮 30 分钟、刮削总预算 8 分钟；外网响应体上限 3MB
- **扫描/刮削解耦（1.5.0）**：扫描路径里不再有任何网络请求，只解析本地文件后立即入库；刮削由后台队列在空闲间隔逐本处理，RSS 超过 300MB 或正在扫描时自动让路。多用户同时打开大书不会再因为刮削抢内存
- **分批与内存护栏**：自动扫描每轮最多 40 本，每 10 本写一次进度心跳（含 RSS/Heap），RSS 超过 256MB 暂停回收、超过 384MB 提前收尾并把剩余留到下一轮，避免被系统强杀；上限可在 `settings.scan` 中调整
- **重任务限流**：CBZ 解压、PPT 逐页解析、图片版 PDF 合成等内存大户共用 2 个并发名额，其余排队；图片版 PDF 回传请求体上限 48MB，超限直接拒绝而不是把内存吃满；PDF 阅读走 Range 分块按需加载（`disableAutoFetch`），上百 MB 的 PDF 不会整本进浏览器
- **后台转换（1.6.0）**：`slideconvert.js` 队列并发固定 1，单本最多 400 页 / 单页 24MB / 总量 160MB 硬上限；PDF 由 `pdfwrite.imagesToPdfFile()` **流式写盘**，不再把整份 PDF 缓冲在内存；封面缓存清理改为异步，避免多版本叠加时保存卡住
- **崩溃取证**：`uncaughtException`、`unhandledRejection`、事件循环阻塞（>1.5 秒）、内存逼近阈值都会记入日志；扫描时把阶段 / 当前文件 / 进度 / 内存持续写入 `running.json`，进程若被 OOM/SIGKILL/断电杀掉，下次启动可直接还原「死在哪本书、当时内存多少」
- **日志不外发**：1.4.1 起彻底取消重启日志邮件与后台补发；日志按天保存最多 2 天，仅在本机「系统日志」页查看。SMTP 仅用于登录验证码与连通性测试

## 打不开 / 升级后无法访问（1.8.2.2）

现象：升级到新版本后，浏览器打开 `https://NAS_IP:8096` 一直转圈或提示「无法访问」，应用中心里却看不出异常。

按顺序处理：

1. **应用中心 → 飞牛书屋 → 停止，等它变成「已停止」，再点启动。** 绝大多数情况到这一步就恢复了。
2. 停止不掉、或启动后仍打不开：在 NAS 上按 PID 强杀一次（1.8.2.2 起新进程也会自己清理，不用手动做）：
   ```bash
   ss -lntp | grep 8096          # 记下 users:(("node",pid=123456,fd=..)) 里的 pid
   kill -9 123456                # 立刻释放端口
   ```
   然后在应用中心点启动即可。
3. 强杀也无效、进程状态是 `D`（卡在磁盘 I/O）才需要**重启 NAS**，其他情况都不用重启。
4. 想确认「是应用卡死还是网络不通」，在 **NAS 本机**执行（不要在别的机器上测，Tailscale 的 TCP 层会误导）：
   ```bash
   curl -k -m 5 https://127.0.0.1:8096/api/site
   ```
   - 返回 JSON → 应用正常，问题在网络/防火墙/端口映射；
   - 超时 → 应用内部卡死，继续看下面的日志与 `ss`。

看确切原因（把路径换成实际安装卷）：

```bash
ss -lntp | grep 8096
ps -o pid,ppid,stat,etime,rss,args -p "$(cat /var/apps/fnbookshelf/var/app.pid 2>/dev/null)"

tail -n 60 /var/apps/fnbookshelf/var/app.log
tail -n 60 /var/apps/fnbookshelf/var/data/logs/$(date +%F).log
cat /var/apps/fnbookshelf/var/data/startup-error.log 2>/dev/null
```

判断口诀：

| 现象 | 含义 | 处理 |
|---|---|---|
| 端口完全连不上 | 进程没起来（脚本拦住了，或崩溃退出） | 看 `app.log` 末尾；端口被别的程序占用时会写明 |
| `ss` 有 LISTEN、`Recv-Q` 持续堆积、`STAT` 是 `R`、CPU 接近 100% | 事件循环被同步代码堵死。`D` 多为同步落盘（1.8.2.2 修），`R` 且日志停在「正文抽样」多为 PDF 正则回溯（1.8.2.3 修） | 升级到 1.8.2.3；临时可 `kill -9` 后重启应用 |
| `STAT` 是 `D` | 进程卡在磁盘 I/O，信号也杀不掉 | 重启 NAS |
| 能打开但书库是空的 | `data.json` 读不出来，已自动备份并重建 | 找 `data.json.bak.<时间戳>`，确认是当前数据目录后再恢复 |
| 启动日志里 RSS 已 >320MB | 书库太大，逼近系统 OOM 线 | 分批整理/拆分数据目录，或加大内存 |

1.8.2.1 起启动时会记一行「书库 N 本 / data.json X MB / 启动内存 RSS Y MB」，并在端口被占时写 `startup-error.log`；1.8.2.2 起端口被**本应用残留进程**占用时，新进程会自动清理它并重试监听，日志里会写「已强制清理（PID …）」。

## 技术架构

- 后端：Node.js 22（打包内置）+ Express，依赖仅 express / nodemailer / fast-xml-parser（ZIP 解析改为内置 `zipread.js`，不再整本载入）；数据为 JSON 文件（原子写入）
- 前端：原生 SPA + epub.js + pdf.js + foliate-js(mobi)，全部本地化
- 刮削：Node 原生 http(s)（自动识别 GBK/GB2312），豆瓣读书 / ISBN 直达 / 当当 / 国家图书馆 OPAC / 读秀多源评分，`scrapeworker.js` 后台空闲队列 + 详情页优先补全，`limits.js` 控制重任务并发
- PPT 转 PDF：`slideconvert.js` 后台队列（并发 1）→ 优先借用系统已有的 LibreOffice，否则 `slideimages.js` 从 PPTX 包逐页抽取整页图 → `pdfwrite.js` 流式合成 PDF → 作为新版本入库；阅读器的浏览器 Canvas 逐页栅格化保留为兼容模式
- 文本与 Word：`textdoc.js` 统一入口（编码判定 + 256KB 检查点索引 + 区间读取），`worddoc.js` 解析 .docx（`zipread.js` 读 OOXML）与 .doc（`cfb.js` 读 OLE 片段表），`mojibake.js` 负责乱码自愈

- AI：OpenAI 兼容 chat/completions；前置本地守卫（话题分类、长度/多问题检测、每日配额）与内容体积硬限制，拒绝不消耗额度；`withDeadline` 硬 5 秒超时，超时回复固定文案且不扣额度
- 日志：`logger.js` 批量异步追加按天日志 + 崩溃取证，`scheduler.js` 本地 0 点扫描，`safeio.js` 大文件护栏
- 安全：HMAC 令牌（24 小时，可吊销 / 可全设备失效）、验证码 10 分钟过期、重发限频、防路径穿越、管理接口双重鉴权；查询串令牌仅限只读资源，`/api/*` 一律 `Cache-Control: no-store`

## 1.8.2 改动：刮削依据、专题、批量版本与大书库稳定性

### 1. 刮削依据按可信度排：文件名优先

以前刮削是「内嵌元数据书名 + 目录名」一起丢给数据源，结果经常被 PDF/EPUB 里的烂标题带偏——
Word 导出的 PDF 元数据常写着 `Microsoft Word - 1234.doc`，扫描件写着 `未命名-1`，反而把用户自己整理的文件名盖掉了。

现在按四级依次尝试，**命中即停**，后面的不再浪费外网请求：

1. **文件名**（用户自己起的名字，最可信）；
2. **文件信息**（书内内嵌元数据，垃圾标题直接跳过）；
3. **存储目录的文件夹名**（含全部层级，最像书名的那一级）；
4. **正文抽样**（前 10 页找书名/作者/ISBN，最费时也最容易跑偏，放最后）。

判定为垃圾的标题：`Microsoft Word - xxx.doc`、`未命名-1`、`001`、`123456`、带文件后缀的标题等；
但 **四位数字书名（如《1984》）照常保留**，不会被当成编号。

### 2. 刮削不再打断你手上的操作

旧实现里，详情页发现这本书还在后台刮削时，会在 4 秒后整页 `render()` 一次（最多两次）。
如果你恰好正在「编辑资料」、正在挑封面、正在勾选版本，页面会被整个重画：弹窗内容、编辑状态、滚动位置全没了，
表现就是「刮削的时候点什么都没反应 / 点两下就失败」。

现在改为**局部更新**：详情页每 3 秒问一次轻量接口 `/books/:id/scrape-status`，只替换书名、出版信息、简介和封面这四个位置；
检测到有弹窗打开时干脆先不动，等你关掉再更新。

### 3. 专题：像文件夹一样归类

- 「全部图书」侧栏下面新增**专题**一栏，点进去就是该专题的书；
- 管理员可新建 / 改名 / 删除专题（删除只删分类，书一本不动）；
- 书库工具栏点 **☑ 选择** 进入多选：可以「全选本页」，然后**加入专题**、**用所选新建专题**、或在专题里**移出本专题**；
- **搜索结果页同样可以多选**——搜完一批书直接建成一个专题，这是这一版最常用的入口；
- 实现上专题只存「作品键」：一本书可以同时属于多个专题，专题里的书在书库里仍然只有一份。

### 4. 版本管理：不弹确认、可批量、可整组打散

- 分离、合并、合并进来**都不再弹二次确认**（误操作随时能合回来，确认框只是拖慢操作）；
- 编辑模式每行前有勾选框，可**勾选多个版本一起分离**；
- 新增 **⇤ 全部打散**：一键把整个作品拆成一本本独立的书（接口 `POST /works/unmerge` 的 `{all: workKey}`）。

### 5. 每页显示多少本

分页条右侧新增 **每页 24 / 48 / 96 / 200 本** 下拉，选择记在浏览器本地；服务端 `limit` 上限由 100 提到 200。

### 6. 大书库扫描崩溃：落盘改成流式写入

崩溃日志里有这么一行：

```
FATAL crash · 启动 · 上次进程未收到正常退出信号；崩溃现场：进度 23429/36526 本、内存 RSS 约 406MB
```

3.6 万本的书库，`data.json` 有 50–100MB。旧实现每次落盘都 `JSON.stringify(this.data)` 一次性生成整份字符串，
再转成写入缓冲——4 万本实测瞬时多占 **176MB**，叠上扫描中的元数据就撞上系统的 OOM 保护线，进程被直接杀掉。

这一版：

| 改动 | 效果（4 万本 / 96MB 的 data.json 实测） |
|---|---|
| 落盘改为**逐 key、逐本书**分块写入（256KB 一批，带背压） | 写盘峰值内存 **176MB → 53MB** |
| 退出兜底 `flushSync` 同样分块 `writeSync` | 关停时不再一次性分配整份 JSON |
| 扫描期间**每 50 本**落一次盘（进度心跳仍是每 10 本） | 写盘 I/O 降到原来的 1/5，磁盘不再被反复写 |
| **每本**都检查 RSS（不再每 10 本才看一眼） | 单本大 PDF/PPT 的瞬时峰值也能拦住 |
| 触发内存护栏时**先落盘再收尾** | 已解析的书不会白扫，重启后接着来 |
| 自动续扫每轮上限 40 → **500 本**，间隔 60s → 20s | 3 万本不再需要「每天 40 本」慢慢磨 |
| 默认内存护栏 256/384MB → **240/320MB** | 提前收尾，不等系统来杀 |

## 1.8.1 改动：找书不再「什么都找不到」

### 1. 找书：从「只让 AI 看 60 本」改成「先在全库找，再让 AI 精选」

问题很直接：旧实现把书库的**前 60 本**塞进提示词让模型挑（2000 本的书库等于只有最近入库的 60 本参与检索），再加上提示词 8KB 上限，问什么都是瞎猜；没配 AI 时整个按钮直接弹「管理员尚未开启」。

现在改成两段式：

- **本地全库召回**（新增 `lib/booksearch.js`）：书名、作者、丛书、出版社、简介、文件名、**存储目录名**一起建倒排索引，中文按二元组切词，BM25 式打分；2000 本首次建索引约 65ms、之后单次检索 <1ms。一句「讲中国近代史、偏通俗的」能直接命中《中国近代史》，不需要任何外部服务、不消耗 AI 额度、断网也能用。
- **AI 只做重排**：把本地前 40 个候选交给模型挑最贴合的几本并给理由，提示词从「整库清单」缩到「候选清单」，又快又稳。AI 超时/报错/没额度/挑不出东西时，**自动退回本地结果**，并在标题下说明原因。
- 结果卡片带「命中『近代史』」这样的理由，找不到时给的是「换个说法」的提示，而不是一个空列表。

### 2. 乱码书名：从「修编码」升级到「修不好就换掉」

上一版只处理了「UTF-8 字节被按 Latin-1 解码」这一种。实际书库里还有把同一批字节按 GBK/Big5/UTF-16 解出来的情况（截图里那种「幙晓驗苷萌諼塵全乜□嚌尉」），单靠反向映射修不回来。这一版三层处理：

1. **判定**：含替换符/□/控制字符直接判为乱码；汉字不少但基本都是生僻字（用 GB2312 一级字库 3755 字做占比）也判为乱码；繁体书名、日文书名不会被误判。
2. **重解**：把字节按 GB18030 / Big5 / UTF-16LE/BE（含错位一字节）重解一遍，用「像人话」打分挑最优（「甯岃厞浜虹殑鏁呬簨」→「希腊人的故事」）。
3. **兜底**：还是救不回来就换名字——优先文件名（顺带清掉「(NEW)」「[扫描版]」「- 副本」这类前缀后缀），文件名也没信息量（`001.pdf`）就用**存储目录名**；手动改过书名的书不参与。

历史数据在启动迁移时自动修一遍，不用重扫；刮削回来的标题如果是乱码也不会再覆盖现有书名。

### 3. 刮削参照「存储目录的文件夹名字（全部层级）」

NAS 上整理图书的习惯往往把有用信息放在目录里（`/图书/中信出版社图书合集2000册/希腊人的故事.pdf`），而文件名可能只剩下编号。现在：

- 刮削查询带上目录层级：书名是 `001`、`(NEW)` 这类没信息量的，先用目录名检索；书名搜不到时再退一步用目录名。
- 打分也认目录名：候选的出版社/丛书名出现在路径里 → 加分；「图书」「电子书」「下载」这类通用容器目录不计入。

### 4. 顺带：TXT 第一行当书名

中文 TXT 常把书名写在第一行。以前只认「书名：」前缀或《》书名号，现在前 500 字里第一行若是短标题（≤24 字、不带句末标点、不是「第 X 章/序/前言/目录」）就直接采用，刮削与同名合并都更准。

## 1.8.0 改动：乱码、大文件与自动归并

这一版全部来自实际使用反馈：一批中文 TXT 打开是乱码、几十 MB 的 TXT 一开就卡死、书库里躺着一堆「第 1 期…第 8 期」、书名里还混进了 `Clipboard_Screenshot` 这种从 PDF/EPUB 元数据里误读出来的乱码。

### 1. 乱码：自动识别 + 历史数据自愈

- 新增 `lib/mojibake.js`：识别并还原「UTF-8 字节被按 Latin-1 / Windows-1252 误解码」的经典乱码（`æŠŠè‡ªå·±…` → 「把自己变成稀缺资产」）。做法是先把字符串按 CP1252 反向映射回原始字节（含 0x80–0x9F 控制区），能按 UTF-8 严格解出中文才采纳，并迭代两次处理二次误码。
- 应用范围：扫描时的书名/作者/简介、PDF 文档信息（`/Title`、`/Author`）、EPUB `dc:title`、OOXML 核心属性。**历史数据也会在启动迁移时自动修一遍**，不用重扫码。
- 顺带修掉一个真 bug：PDF 文本串的八进制反转义把整个匹配（`\346`）当成数字传给 `parseInt`，得到 `NaN`，中文标题会变成一串 `\u0000`——现在取捕获组，标题能正确还原。
- 新增 `lib/textdoc.js` 的编码判定：BOM（UTF-8/UTF-16LE/BE）→ 无 BOM 的 UTF-16（零字节比例）→ UTF-8 严格校验 → GB18030 / Big5 打分（中文占比减去替换符惩罚）。刮削用的书名作者改为读**正文前 500 字**，不再依赖文件名。

### 2. 大文件：TXT 不再整本进浏览器

- 服务端新增 `GET /api/books/:id/text?from=&count=`：按 256 KB 块建检查点索引，只返回请求的段落区间，切块时按换行对齐（UTF-8 / UTF-16 各自处理，不会切出半个汉字）。
- 阅读器只渲染当前视口附近的 80 段，滚到底自动续、往回滚自动补头部；目录跳转直接换算成段落号请求。实测 15 MB / 60000 段的 TXT，建索引约 120 ms，首屏内存与文件大小无关。
- Word 文件同样走这条通道（见下条），不再一次性把解析结果塞进 DOM。

### 3. Word：.docx 与旧版 .doc 都能在线读

- `lib/zipread.js` 按条目读 `word/document.xml`，抽段落并保留粗体/斜体/标题层级（`w:pStyle` 的 Heading 映射成 h2/h3/h4），目录据标题层级生成。
- `lib/cfb.js` 解析 OLE/CFB 复合文档，`lib/worddoc.js` 走 `WordDocument` 流的片段表（piece table）拼正文；片段表异常时退化为 `fcMin..fcMac` 连续区，再退化为启发式 UTF-16LE 扫描，ANSI 段落优先按 GB18030 解码。
- 实测一份 WPS 生成的 `.doc` 合同抽出 4926 字、0 个替换符。

### 4. 自动归并：同名合一、系列成册

- 扫描结束后跑一次幂等的 `lib/grouping.js`：
  - **同名先合并**：书名相同（作者还是占位名时）直接归到同一部作品；
  - **刮削后再判**：同名组里出现两个不同的可信作者，说明本来就是两本书，自动拆开；
  - **系列聚合**：同一目录下、文件名只差期号/年份的（`第1期…第8期`、`2013/2014 xxx`）合成「×× 系列」，各期作为版本出现在同一个详情页。只差扩展名（`.pdf`/`.epub`）或副本后缀（`xxx (1).txt`）不算系列，仍按同名合并。
- 手动合并或分离过的书打上 `groupLocked`，之后重扫不再被自动调整；自动改名的书保留 `titleBeforeSeries`，条件不再成立时能还原原名。
- 归并只在元数据层面重排，**不动任何源文件**。

### 5. 其余四条体验改动

- **管理员可见存储路径**：详情页显示源文件完整路径（点击复制），版本管理每一行也带自己的路径；非管理员不下发该字段。
- **入库文件类型**：管理后台「图书库 → 入库文件类型」逐项勾选允许入库的后缀，另可手填额外排除项；取消勾选后下次扫描直接跳过，重新勾上即回到书库，NAS 源文件不受影响。
- **页码直达**：全部图书底部加「共 N 本」与页码输入框，回车或点「跳转」直接到指定页。
- 阅读器顶部新增一行提示：当前文件的**编码**与**总段数**，遇到异常文件一眼能看出判定结果。



## 1.7.1 改动：第二轮复测收尾 + 版本独立下载 + PPT 只转一次

第二轮复测报告给出的结论是「11/12 已关闭，剩 1 项权限遗漏」，这一版把它连同两条遗留低危一并收掉，同时按使用反馈改了两处体验。

### 1. M-1：切换默认版本补上权限守卫

`PUT /api/works/:workKey/default` 之前漏在 `requireEditor` 之外——封面、合并、分离、元数据都拦了，只有它会放普通用户过去。现在它与其余书库写操作走同一条线：默认仅管理员，管理后台开启「家人共同管理」后可放开；同时写入审计留痕。前端在无权时不再渲染「设为默认」按钮。

### 2. L-4：转换类接口全部收口

- `POST /api/books/:id/convert`（后台逐页取图转 PDF）与 `POST /api/books/:id/slides/pdf`（浏览器渲染后回传入库）都是**会向书库写入新版本**的写操作，现在都需要编辑权限——鉴权在查资源之前，所以用不存在的 bookId 探测会先拿到 403 而不是 404。
- `GET /api/convert/:jobId` 增加归属校验：普通用户拿到别人的 jobId 只会得到 404，读不到书 ID、页数与错误信息。

### 3. `?token=` 收敛到只读资源

查询串令牌只为「浏览器自己发起的、加不了请求头」的请求保留：封面 `<img>`、原文件下载与 pdf.js 分块、PPT 页面内嵌图、CBZ 逐页、封面候选预览、`<audio>`、管理员「测试下载」、阅读时长心跳（sendBeacon 兜底）。

`/api/me`、`/api/books`、`/api/settings` 等接口一律只认 `Authorization` 头——令牌不会再出现在 NAS 访问日志、浏览器历史与截图里。

### 4. `/api/*` 统一 `no-store`

含用户数据的响应（`/api/me`、`/api/books`、`/api/site`、错误响应）全部带 `Cache-Control: no-store` + `Pragma: no-cache`，避免局域网透明代理或共用浏览器缓存后串读他人数据。封面与逐页图片仍保留 `private, max-age`，翻页性能不受影响。

### 5. 版本管理：每个文件都能单独下载

版本栏每行的按钮变为 **阅读 → ⬇ 下载 → 申请删除**（编辑模式下末尾再多一个「分离」）。下载走与详情页相同的三级兜底（iframe 新窗口直开 → fetch 成 Blob → 再直开），自签名 HTTPS 与飞牛桌面 iframe 下都能落盘；文件名保留该版本自身的名字与扩展名。窄屏下按钮自动换行，不会挤压文件名。

### 6. 同一个 PPT 只转换一次

转换产物（`generatedFrom` 指向源文件、且文件仍在）存在时：

- 详情页「⚙ 后台转换」变灰，提示先在版本管理里删除那个 PDF；
- 阅读器不再出现「存为 PDF」按钮，改为提示已生成；
- 接口层返回 `409` 并说明解锁方式（后台转换、浏览器存为 PDF 两条路都拦）；
- 删除该 PDF 版本（管理员批准）后，源书上的 `convert` / `imagePdf` 记录一并清空，锁自动解开，可以重新转换一次。

这样既不会重复占用转换队列与磁盘，也不会在版本栏里堆出多个内容相同的 PDF。

## 1.7.0 改动：按安全评估报告逐条加固

这一轮不改功能，只修安全问题。报告里的 1 高危 / 7 中危 / 6 低危逐条对照如下。

### 1. 高危：验证码校验缺失（可无验证码注册）

**问题**：`POST /api/auth/verify` 在「该邮箱从未请求过验证码」时不会进入校验分支，而是直接落到注册逻辑——任意邮箱 + 随机 6 位数字就能建号，且以 `403` 返回「注册成功」，状态码与语义矛盾。

**修复**：把「存在未过期 challenge」做成登录/注册的**前置硬条件**：

```
请求 → 有 challenge？ --否--> 400 请先获取验证码（结束，绝不建号）
                       --是--> 校验验证码（一次性、5 次上限、定长比较）
                                └→ 通过后才判断「已注册 / 未注册 → 建号」
```

- 待审核注册的响应从 `403 + pending` 改为 `200 + {ok:true, pending:true}`。
- 离线解锁码路径保留，但按 IP 限 8 次/小时。

### 2. 认证接口限流（三层配额）

| 入口 | 限制 |
|---|---|
| `POST /api/auth/code` | 每 IP 10 次/小时 · 全站 120 封/小时 · 1 小时内不同收件人 > 30 即熔断 |
| `POST /api/auth/verify` | 每 IP 40 次/15 分钟（另有每邮箱 5 次错误上限） |
| 离线解锁码 | 每 IP 8 次/小时 |

计数键用 `req.socket.remoteAddress`，并显式 `app.set('trust proxy', false)`——伪造 `X-Forwarded-For` 无法换桶。「不同收件人」这一层专门堵「换个邮箱重新计数」的垃圾邮件放大。

### 3. 账号枚举

`POST /api/auth/code` 不再返回 `registered` 字段，登录页文案统一为「验证码已发送」。是否已注册只体现在邮件内容里（未注册的邮件带注册引导）。

### 4. 令牌生命周期

原来：7 天、无状态、无登出接口、payload 只有 `uid` → 泄露后 7 天内无法止损。

现在：

- **有效期 24 小时**（后台「安全」页可在 1–168 小时间调整），到期必须重新验证邮箱；
- **滑动续期**：剩余寿命不足一半时，响应头带 `X-Refresh-Token`，前端静默替换，正常使用不会被打断；
- **`ver` 会话版本号**：改角色、禁用账号、「退出所有设备」都会自增，旧令牌**立即**失效；
- **`jti` + 黑名单**：`POST /api/auth/logout` 让当前令牌立刻作废（前端「退出登录」现在会真的调用它，而不是只清 localStorage）；
- `POST /api/auth/logout-all` 一键踢掉所有设备；
- 签名比较改为 `timingSafeEqual`，禁用账号的旧令牌直接判无效。

### 5. 授权粒度：影响他人的操作归管理员

`POST /api/books/:id/cover`、`POST /api/works/merge`、`POST /api/works/unmerge` 原来任何登录用户都能调（能静默改掉全站封面、拆散别人整理好的版本分组），现在默认 **仅管理员**；管理员可在「安全 → 允许普通用户管理书库」放开给家人。

同时新增**敏感操作留痕**（`data.audit`，最近 500 条）：合并/分离、封面、删除申请、用户改角色、安全设置变更都会记录「谁在何时对什么做了什么」，后台「安全」页可直接查看（`GET /api/logs/audit`）。

> 注：报告里列的 `PUT /api/works/:workKey/default` 实际是**按用户存储**的（`data.defaultVersion[userId][workKey]`），普通用户改只影响自己，因此保持开放。

### 6. 绝对路径泄露

`POST /api/books/:id/delete-request` 的响应里原来带 `path: /vol1/1000/books/…`；版本列表、`/api/works/:workKey` 也会下发同样的路径。现在这些字段**只对管理员返回**，普通用户拿到的是书名、文件名等展示字段。

### 7. 安全响应头

所有响应统一注入（`app.js` 顶部中间件）：

```
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
  img-src 'self' data: blob:; font-src 'self' data: blob:; media-src 'self' data: blob:;
  connect-src 'self' blob:; worker-src 'self' blob:; frame-src 'self' blob: data:;
  object-src 'none'; base-uri 'self'; form-action 'self';
  frame-ancestors 'self' https://<同主机>:* http://<同主机>:*
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Permissions-Policy: geolocation=(), microphone=(), camera=(), payment=()
Strict-Transport-Security: max-age=31536000   （仅 HTTPS）
```

关于 `X-Frame-Options`：应用要嵌在飞牛桌面（同一 NAS 的另一个端口）里，而 `X-Frame-Options` 只能表达「同源」，无法表达「同主机任意端口」，所以这里用 CSP `frame-ancestors` 精确放行，不再设置 XFO。若要额外放行别的域名（例如反代后的桌面域名），在「安全」页填写即可；填 `'none'` 则完全禁止被嵌入。

`script-src 'self'` 不需要 `'unsafe-inline'`（前端没有内联脚本），这是 CSP 最有价值的部分；`style-src` 放开 `'unsafe-inline'` 是因为界面大量使用 style 属性。

### 8. 软 404 与错误页

- 未知路径返回**真实 404**，不再「200 + 首页」。前端是 hash 路由，不需要服务端兜底；只有「GET + Accept 含 text/html + 路径无扩展名」才给一张友好的 404 页，其余纯文本 404。目录扫描（`/.env`、`/phpmyadmin` 等）不再是 200。
- 未匹配的 `/api/*` 返回 `{"error":"not found"}`；5xx 一律回 «服务器内部错误»，堆栈只进日志。
- 错误响应不再出现 Express 英文默认页。

### 9. 查询串令牌的收敛

报告指出的「Token 会进日志 / Referer」链路，分三层收敛：

1. `Referrer-Policy: no-referrer`——外链图片再也不会把带令牌的 URL 当 Referer 发出去；
2. **写操作不接受 `?token=`**（只接受 `Authorization` 头），只剩 `GET/HEAD` 的 `<img>`、`<a download>`、pdf.js 取文件还能用查询串；唯一例外是阅读时长心跳（页面卸载时用 `sendBeacon` 上报，无法加头），且前端已改为 `fetch(keepalive)` + Authorization，仅旧缓存前端会走例外；
3. 令牌本身 24 小时到期 + 可吊销（见第 4 条），泄露后的窗口从 7 天压到小时级。

> 仍未做：把查询串令牌换成「5 分钟一次性签名 URL」。这需要前端所有静态资源 URL 都走一次签名接口，改动面很大且收益有限（有了 1+2+3 之后，泄露窗口已经很小）。如后续要彻底消除，可在 `auth.js` 里加 `signMedia()` 并在 `/read`、`cover-options` 等返回 URL 的地方替换。

### 10. 其他

- `/api/auth/code`、`/api/auth/verify` 入口强类型校验：`email` 传数组/对象一律 `400`，不再被 `String()` 隐式转换。
- 未登录访问 `/api/site` 只返回 `siteName` 与 `registerMode`；抓取源、AI/TTS 开关、HTTPS 模式只在登录后返回。
- 后台「🔒 HTTPS」标签改为「🔒 安全」，新增登录有效期、iframe 白名单、「家人共同管理」开关、「退出所有设备」、「查看敏感操作记录」。

### 11. 顺带核实的两个盲区

- **命令注入**：`office.js` / `slideconvert.js` → `execFile(soffice, [args…])`、`app.js` → `execFile(openssl, [args…])`，全部是参数数组，唯一的 `sh -c` 是常量 `command -v soffice`。文件名/路径不经过 shell，**不存在命令注入**。
- **自签名证书（低危，运维项）**：应用只能生成自签名证书，浏览器必然告警；这不是代码能修的，需要换成正式证书（Let's Encrypt）或在客户端导入自建 CA。后台「安全」页的证书上传框已支持粘贴 PEM。

## 1.6.3 改动：PPT 改为浏览器直接渲染 + 下载/封面崩溃修复

### 1. 为什么不再依赖服务端转换

1.6.0–1.6.2 的链路是「服务端解析 PPT → 抽整页图 → 合成 PDF」。这条路对图片型 PPT 有效，但在真实 NAS 上仍会踩三个坑：

- 服务端要读源文件、还要写同目录 PDF。数据目录/书库一旦有权限问题（本次崩溃日志里的 `EACCES`），整条链路直接失败，且错误信息只停留在任务里。
- 图片型 PPT 抽出来的是「整页截图」，纯文字的标题/版权页没有整图可抽，只能跳过或补空白页，页码与源文件对不上。
- 生成的 PDF 是位图：放大发虚、不能选中文字、不能搜索。

1.6.3 起默认**不调用服务端转换**：阅读器用 `fetch` 取回原文件，交给随包分发的 `@web-ppt/core`（MIT，runtime 只依赖打包进去的 fflate）解析成统一模型，再逐页渲染成自包含 SVG。

- **`.pptx` 与旧版二进制 `.ppt` 共用一条通道**。后者是 OLE/OfficeArt 老格式，绝大多数前端库只支持 `.pptx`；本项目主诉文件正是这种。
- 文字是 `<text>`（可选中、可搜索），图片以 data URL 内嵌，缩放不糊。
- 懒渲染：`IntersectionObserver` 滚动到哪页渲染哪页。样例 29 页 / 5.2 MB 的扫描绘本：解析约 0.17 s，整本渲染约 0.45 s，首屏只渲染 1 页。
- 工具条：上一页 / 下一页 / 页码 / 缩放（适应屏幕 · 适应宽度 · 100%）；键盘 ← →、PgUp/PgDn、Home/End 可用；进度按页写入阅读记录。

### 2. 「存为 PDF」改由浏览器出图

点右下角「存为 PDF」：浏览器用 `slideToPng` 把每页光栅化（1.6 倍分辨率）→ 一次性 POST 到既有的 `POST /api/books/:id/slides/pdf` → 服务端用 `pdfwrite` 合成 PDF 并**登记为同一本书的新版本**。

这条链路完全不碰服务端的 OLE/OOXML 解析，所以不会再出现「后台转换失败」；产物与屏幕所见一致（标题页也在内）。实测 29 页全部入库，`versions` +1。

### 3. 兜底顺序（渲染失败时）

面板给出四个出口，并显示真实错误：重试直接渲染 / ⚙ 后台转换为 PDF（原 1.6.2 链路）/ 🖥 逐页绘制（兼容模式）/ ⬇ 下载原文件。

### 4. 下载：三级兜底 + 自检

浏览器拦下载的成因不止一种，1.6.2 只堵了其中一种：

1. 自签名 HTTPS 页面里 `<a href download>` 被 Chrome 拦（下载列表「无法下载 - 网络问题」）；
2. 应用被嵌在飞牛桌面的 iframe 里，沙箱没有 `allow-downloads` 时下载被静默丢弃；
3. 企业策略 / 隐私插件拦 `blob:` 下载。

现在的 `saveFile()`：**iframe 内先新窗口直开附件地址** → `fetch` 取回 Blob 保存 → 再退「新窗口直开」，最后把「可直接粘贴到地址栏的链接」写进失败提示。服务端侧：`sendRangeFile` 先 `accessSync(R_OK)` 检查可读，不可读时返回 403 并说明「权限不足」，而不是让流错误冒泡。

后台「数据位置」新增 **⬇ 测试下载**（取回一个几十字节的 txt 附件）：能落盘说明浏览器允许下载、问题只在具体文件；仍失败就是浏览器/沙箱拦了。

### 5. 封面 EACCES 导致崩溃

日志里的 `EACCES: permission denied, open '/vol1/1000/books/covers/xxx.jpg'` 来自 `fs.createReadStream(f).pipe(res)`：流的 `error` 事件没人接，升格成 `uncaughtException`，`logger.install()` 又直接 `process.exit(1)` → 「启动几秒就崩、被拉起再崩」的死循环。

三处一起改：

- `/api/cover/:id` 先 `accessSync(R_OK)`，再给流挂 `error` 处理器，出错回退到内置占位封面；
- 新增 `streamFile()` 统一封装所有流式响应（封面候选、媒体、TTS、下载等 8 处），读取失败只影响本次请求；
- `logger.install()`：`EACCES/EPERM/ENOENT/EISDIR/EBUSY/EPIPE/ECONNRESET` 等文件系统/网络类异常只记 ERROR 并继续服务；真正的逻辑异常仍然退出并保留崩溃现场。

诱因通常是**数据目录被迁移/拷贝过，文件属主是 root**，而应用以 `package` 用户运行。因此后台「数据位置」新增 **🩺 存储自检**：显示进程 UID/GID、数据目录是否可写、封面与图书各有几个不可读并给出示例路径，附「🔧 尝试修复权限」（chmod 目录 775 / 文件 644）。属主不是本进程时 chmod 也会失败，界面会提示改用 root 执行 `chown -R fnbookshelf:fnbookshelf <数据目录>` 或切回应用默认数据目录。

### 6. 其他

- 书籍详情页移除「目录」栏目（阅读器内的左侧目录仍保留）。
- 打开 PPT 时一律进入直接渲染；若此前已有图片版 PDF，工具条多一个「PDF 版」按钮供切换。

## 1.6.2 改动：旧版 .ppt 取图转换 + 下载拦截修复

### 1. 二进制 .ppt 为什么以前不能读，现在怎么读

- **以前**：`slideconvert.js` 对 `ext === 'ppt'` 是**无条件抛错**（自研链路只认 OOXML 的 `.pptx`）；兼容模式用的 `pptbin.js` 只解析 `TextCharsAtom`/`TextBytesAtom` 两种文本记录，图片型 `.ppt` 解析结果是 `slides: []`，阅读器既没有页面、也没有「下载原文件」出口，表现就是「打不开」。
- **现在**：`pptbin.js` 重写，新增 OLE/CFB → 记录树 → 图片三件套：
  - `parseDeck()`：按顶层 `Document` 块切分（多块是增量保存的修订版，取幻灯片最多的那块），每页收集文本与 `pib`（`OfficeArtFOPT` 属性 `0x0104`）。
  - `parseBlips()`：解析 `Pictures` 流里的 BLIP 记录（JPEG/PNG 魔数定位 + `jpegInfo` 校验），得到按 `pib` 编号的图片数组（`pib` 从 1 起）。
  - `extractPptImages()`：按页序把 `pib` 翻成真实图片，纯文字页跳过并报 `skipped` 数；`parsePpt()` 则把图片落成 `cache/slides/<bookId>/` 下的媒体文件给兼容模式用。
- **关键约束**：图片按 `pib` 对页，**不按图片流顺序猜页序**——同一张图可能被多页复用（本项目样例里第 18、19 页就是同一张），顺序猜会直接错位；单本 ≤400 页、单页 ≤24MB、总量 ≤160MB 的护栏与 `.pptx` 一致；转换队列并发仍为 1。
- **样例实测**（29 页扫描绘本 `阿罗在北极.ppt`，5.2MB）：`Pictures` 流 27 张 JPEG（最大 750×493）、幻灯片 29 页、纯文字标题页 1 页 → 合成 28 页 PDF，逐页图片字节与 PDF 内嵌流长度一一对应；OCR 无关，图片原样嵌入（`DCTDecode`），不二次压缩。

### 2. 「点击下载提示 无法下载-网络问题」

- **先排除服务端**：本地起服务实测 `GET /api/books/:id/file?download=1` → `200`、`Content-Length` 与文件大小一致、`Content-Disposition: attachment; filename*=UTF-8''…`、`Range` 请求 `206` 正常，字节数与源文件完全相同。所以不是接口问题。
- **真因**：应用默认用**自签名证书**跑 HTTPS。Chrome 对「证书不受信任的页面」会拦截 `<a href download>` 直接发起的下载，下载列表里显示「无法下载 - 网络问题」（页面本身能开，是因为用户点了「继续前往」）。
- **修复**：详情页与阅读器的「下载」改为 `fetch()` 取回内容 → `Blob` → 本页 `blob:` 地址 + `a.download` 保存（`app.js` 的 `saveFile()`）。`blob:` 不发起跨网络下载，因此不受该拦截；失败时弹出真实原因（HTTP 状态/空文件）并提示可上传受信任证书或改用 NAS 域名访问。
- **根治建议**：在「设置 → HTTPS」上传受信任证书（或 `mode: off` 交给 fnOS 反代终结 TLS），浏览器就不会再拦任何下载。

### 3. 顺带修复

- `/slides` 只在**有令牌**时才给图片地址拼 `?token=`，避免出现空 `token=`。
- 鉴权中间件容忍重复的 `token` 查询参数（取最后一个），避免拼 URL 时重复导致莫名 401。
- `.ppt` 解析模型结构变了（新增 `pictures` 字段），旧的结构缓存自动失效重解析。
- 兼容模式失败判定从「容器里有没有子节点」改为「`buildPptRender()` 的返回值」——原先前者永远为真，错误分支从来不会显示。



## 1.6.0 改动的实现范围与关键约束（1.6.2 的补充见上一节）

### 1. PPT 转 PDF（调研结论 + 替代方案）

**调研结论**：飞牛 fnOS 官方预览套件（`trim.preview` / 文档在线预览）走的是 LibreOffice / OnlyOffice DocumentServer 一类完整 Office 渲染引擎，属于数百 MB 级、常驻内存数百 MB 的独立组件，还要配套字体与沙箱。这与「不安装大量第三方软件」「降低内存占用」的既有约束直接冲突，因此**不复刻**，改走零依赖自研链路。

| 项 | 范围 / 约束 |
|---|---|
| 触发 | 详情页「转换」按钮 → `POST /books/:id/convert` 建后台任务；阅读器里也保留「浏览器渲染（兼容模式）」入口 |
| 引擎优先级 | ① 系统**已经**装了 `soffice`/`libreoffice` → 直接借用（只 `command -v` 检测，**绝不安装**），保真度最高；② 否则 `.pptx` 由 `slideimages.js` 从 OOXML 包按页序抽取「面积 ≥ 整页 45%」的整页图片、`.ppt` 由 `pptbin.js` 从 OLE `Pictures` 流按 `pib` 取整页图（1.6.2）；③ 都不行则明确报错，不静默产出空白 PDF |
| 支持范围 | **图片型 `.pptx` 与旧版二进制 `.ppt`**（每页本来就是一张截图，正是书籍类 PPT 的常见形态；1.6.2 起 `.ppt` 走 OLE 图片流）；纯文字/矢量页、WebP/EMF 图片不在自研链路内，需用兼容模式或系统 LibreOffice |
| 页数护栏 | 单本 ≤400 页、单页 ≤24MB、全部页面图片合计 ≤160MB；每 4 页让出一次事件循环；转换队列并发固定 1 |
| 产物 | `原名.阅读版.pdf` 写回**源文件同目录**（目录不可写时退到应用缓存目录）；`pdfwrite.imagesToPdfFile()` 流式写盘，不把整份 PDF 缓冲进内存 |
| 入库 | 作为**同一部作品的新版本**登记（`generatedFrom` + 内部派生标记），沿用源书元数据/封面并设为默认版本；**不新建独立书籍、不覆盖源文件**，重扫时派生 PDF 会被跳过、不会重复入库 |
| 兼容 | `imagePdf` 字段保留，源 PPT 的 `/read` 直接指向产物 PDF；已有的浏览器逐页栅格化链路保留为兜底 |

### 2. 合并书籍交互

- 范围：书库页顶部「合并书籍」开关 → 进入合并模式后，**点选两本书**或**按住拖动**完成合并；退出模式后卡片恢复正常点击进详情。
- 约束：**完全移除 HTML5 `draggable`**（浏览器会把文字/图片拖拽解释成搜索或新开标签页），改用 `pointerdown/move/up` + 自绘浮标；`dragover/drop` 一律 `preventDefault`，卡片与图片设 `user-select:none` / `-webkit-user-drag:none` / `touch-action:none`；拖动结束抑制一次 click，避免误进详情。合并前仍需确认。

### 3. 版本管理栏

- 范围：**单版本也常显**并列出当前文件；「编辑」里可搜索并合并其他书籍、把某个版本「分离」为独立书籍（重新分配 `workKey`）。
- 约束：分离只改索引关系，**不移动、不复制、不删除任何磁盘文件**；派生 PDF 版本同样可分离；删除仍需走「删除申请 → 管理员审核」。

### 4. 封面设置

| 来源 | 约束 |
|---|---|
| 刮削 / 内嵌封面 | 沿用现有封面文件；没有封面时给出明确提示，可借用同作品其他版本的封面 |
| 同目录图片 | 只读**书籍文件所在目录**，最多 60 张、单张 ≤20MB，支持 jpg/png/webp/gif/bmp；文件名严格 `basename` 校验，拒绝 `../`、绝对路径与路径穿越 |
| 书内某一页 | 仅 PDF / CBZ / 已转换 PPT 可选页；浏览器用 pdf.js 或 `/page-image` 渲染，回传 base64 ≤8MB 且 ≥2KB；其他格式提示改用同目录图片 |

- 手动封面标记 `coverSource=manual`，**重扫与刮削都不会覆盖**；「恢复自动封面」可解除锁定。同一部作品的所有版本一起更新，卡片与详情保持一致。

### 5. 已读完

- 范围：`/me/stats` 新增「✅ 已读完的书籍」＝ **手工点「读过」 ∪ 阅读进度 ≥100%**，两路取并集去重；详情页「○ 标为读过 / ✓ 已读完」可切换。
- 约束：标记时同步把进度写到 100%；**撤销时把 100% 退回 99%**（保留 cfi/页码），否则统计页会因进度仍为 100% 又把它算回来。纯前端按钮状态与服务端 `finished` 表保持一致。

### 6. 安装报「设置目录权限失败」的真正原因与修复（1.6.1）

- **真因**：1.5.0 为缩小安装包剔除了 Node 运行时的 `lib/node_modules/`，但 `bin/npm`、`bin/npx`、`bin/corepack` 都是**指向该目录的软链接**，只排除了前两个，`node/bin/corepack` 留了下来，成了一个指向不存在文件的**断链软链接**。fnOS 安装阶段会对应用目录递归执行 `chown` / `chmod` / `setfacl -R`，递归进入该断链时返回 `ENOENT`，安装器随即报「无法安装 fnbookshelf / 设置目录权限失败」。
- **证据**：1.4.1 与 1.5.0 的 `config/`、`wizard/`、`cmd/` 逐字节相同（`diff -r` 零差异），唯一变化就是包结构；1.4.1 包内 3 个软链接目标齐全 → 安装正常，1.5.0 起只剩 1 个断链 → 安装失败。
- **修复**：`build.sh` 在 `tar -xf` 中一并排除 `bin/{npm,npx,corepack,yarn,pnpx}`，并新增**打包前断链自检**——清理后若仍存在任何断链软链接，直接中止打包并打印清单，从源头阻断该问题复发；`cmd/install_callback` 额外清理升级场景可能残留的断链。
- **不是** `privilege` 的问题：上一轮怀疑「显式 `username`/`groupname` 与系统已有账号冲突」，经复核不成立，`config/privilege` 已恢复为 1.4.1 已验证可安装的原样（`run-as: package` + `username`/`groupname`）。
- **约束**：断链自检在打包机本地执行（Windows Git Bash 与 Linux 均可用 `find -type l` + `test -e` 判定）；已经安装失败过的机器无需清理残留用户/组，直接用 1.6.1 重装即可。图书目录的外部访问仍需在「设置 → 应用 → 授权管理」手动授权。

### 7. 顺带修复与性能

- 鉴权中间件把 token 挂到 `req.authToken`，`cover-options` 用它拼图片 URL——修复前端走 Authorization 头时封面候选图 401。
- `POST /books/:id/cover` 加入全局 `jsonSmall` 排除名单，避免请求体被两个 body parser 重复消费导致请求永久挂起。
- 封面缓存清理改为「先写目标文件、再异步删其他扩展名」，避免 Windows 上逐次 `unlinkSync` 失败带来的数百毫秒延迟（实测保存从 ~2.7s 降到 ~50ms）。
